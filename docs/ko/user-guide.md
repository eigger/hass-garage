# 사용 안내와 문제 해결

[English](../user-guide.md) | [한국어](user-guide.md) | [README](../../README.ko.md)

## 요구사항

- Home Assistant **2025.3.0 이상**, 네트워크로 접근 가능한 셀프호스팅 [Garage](https://github.com/eigger/garage) 서버와 차량별 API 토큰.
- 로컬 HTTP/HTTPS 통신(`POST /api/ingest/telemetry`, `GET /api/ingest/status`, `GET /api/ingest/reminders`)을 사용하며 Bluetooth 어댑터나 프록시는 사용하지 않습니다.

## 설치

1. 이 저장소(`eigger/hass-garage`)를 HACS의 사용자 지정 저장소(**Integration**)로 추가하거나, `custom_components/garage` 폴더를 Home Assistant 설정 디렉터리의 `custom_components/` 아래에 복사합니다.
2. Home Assistant를 재시작합니다.
3. **설정 → 기기 및 서비스 → 통합구성요소 추가 → "Garage 차량관리"**를 선택합니다.
4. Garage 서버 주소(예: `http://192.168.1.50` 또는 `https://garage.example.com`)와, Garage 웹 UI **차량 상세 → OBD & GPS** 탭에서 확인할 수 있는 해당 차량의 **API 토큰**을 입력합니다.
5. 이어서 전송할 센서(위치/RPM/속도/연료/주행거리)를 고르는 화면이 뜹니다 — 지금 안 고르고 비워둬도 되고, 나중에 옵션에서 언제든 설정할 수 있습니다.

차량 한 대당 통합구성요소 항목을 하나씩 추가합니다(여러 대를 등록하려면 통합구성요소를 여러 번 추가하세요). 제거할 때는 통합구성요소 항목을 삭제한 뒤 HACS에서 제거하거나 `custom_components/garage` 폴더를 삭제하고 재시작합니다.

## API 토큰 발급

Garage 웹 UI에 관리자로 로그인 → 해당 차량 상세 페이지 → **OBD & GPS** 탭에서 확인할 수 있습니다. 이 토큰은 로그인 없이 텔레메트리를 주고받는 용도로, 차량마다 하나씩 자동 발급되어 있습니다. 토큰이 재발급되거나 거절(`401`)되면 Home Assistant의 재인증 화면에서 새 토큰으로 갱신할 수 있습니다.

## HA → Garage로 자동 전송하기

통합구성요소 카드의 **"구성"(옵션)**에서 전송할 엔티티를 고릅니다. 나중에 센서를 바꾸고 싶으면(고장, 교체, 새 센서 추가 등) 같은 화면을 다시 열어서 바꾸면 됩니다 — 저장하는 즉시 자동으로 재로드되어 새로 고른 센서로 바로 반영됩니다.

| Garage 필드 | 어떤 엔티티를 고르면 되나 |
| --- | --- |
| 위치(위도+경도) | 위도/경도 속성을 함께 갖는 `device_tracker` 엔티티 하나(예: 휴대폰 위치, OwnTracks, Traccar) |
| 엔진 회전수(RPM) | RPM `sensor`(ESPHome OBD 리더 등) |
| 속도 | 속도(km/h) `sensor` |
| 연료/배터리 잔량 | 퍼센트(%) `sensor` |
| 주행거리 | km 단위 `sensor` |

전부 선택 사항입니다 — 갖고 있는 센서만 고르면 됩니다.

- **위치 제외 트리거**: 전송 트리거는 **위치를 제외한 나머지 값(RPM/속도/연료/주행거리)이 바뀔 때만** 걸립니다 — 위치는 주행 중 계속 바뀌므로 트리거에 넣지 않고, 트리거가 걸린 시점의 최신 위치를 함께 실어 보냅니다.
- **최소 전송 간격(디바운스)과 순서 보장**: 같은 순간에 여러 번 바뀌면 **최소 전송 간격**(기본 10초, 옵션에서 1~300초로 조절 가능) 안에 묶어서 한 번만 보내고, 실제 전송은 직렬화되어 있어 여러 전송이 겹쳐도 발생한 순서 그대로 서버에 도착합니다. RPM처럼 1초 단위로 계속 바뀌는 센서를 쓴다면 이 간격을 늘려서 요청 빈도를 줄일 수 있습니다.
- **재시작 복구 이벤트 무시**: HA를 재시작하면 트리거 엔티티가 잠깐 `unknown`/`unavailable`("알 수 없음/사용 불가")이었다가 원본 통합구성요소가 다시 붙으면서 마지막 값으로 돌아오는데, 이건 실제 값 변화가 아니므로(값이 사라지는 경우도 마찬가지) 전송을 트리거하지 않습니다.
- **진단 센서("마지막 전송 시각")**: 정상 동작 여부는 진단 센서 **"마지막 전송 시각"**(`last_push_at`, timestamp 타입)으로 확인할 수 있습니다 — 성공 여부(`success`)와 실제로 전송한 엔티티 목록(`forwarded_entities`)은 이 센서의 속성으로 함께 들어 있으며, 직전 전송이 실패하면 아이콘이 `mdi:alert-circle`로 바뀝니다. 전송할 엔티티를 하나도 고르지 않은 상태에서는 **마지막 전송 시각** 센서와 **지금 전송** 버튼이 `unavailable`(사용 불가)로 표시됩니다.
- **수동 실행 버튼**:
  - **지금 전송**(`push_now`): 디바운스 대기 없이 텔레메트리를 즉시 한 번 보냅니다(대기 중인 지연 전송이 있으면 취소). HA 재시작 직후처럼 실제 값이 안 바뀌어서 자동 전송이 안 걸리는 상황에서 유용합니다.
  - **지금 새로고침**(`refresh_now`): 상태(5분)·리마인더(30분) 폴링 주기를 기다리지 않고 즉시 다시 조회합니다.

## Garage → HA로 자동 수신되는 센서

| 센서 | 내용 | 갱신 주기 |
| --- | --- | --- |
| 위치(`device_tracker`) | 마지막으로 알려진 위·경도(`location_updated_at` 속성 포함) — 지도에 표시됨 | 5분 |
| 지난·임박 리마인더(`sensor`) | `isDue` 또는 `isUpcoming`인 정비/행정 리마인더 개수(Garage 대시보드의 "지난/임박" 배지와 동일 기준, `due_count`·`upcoming_count`·`due_types`·`upcoming_types` 속성 제공) | 30분 |

주행거리·연료/배터리 잔량·속도는 애초에 HA 쪽 엔티티가 Garage로 보내는 원본 값이라, Garage가 그걸 다시 계산해서 HA에 표시하는 중복 센서는 두지 않았습니다.

## 사용 예시

```yaml
action: button.press
target:
  entity_id: button.my_car_push_now
```

```yaml
action: button.press
target:
  entity_id: button.my_car_refresh_now
```

엔티티 ID는 예시이며 실제 설치에서 생성된 차량의 **지금 전송** 또는 **지금 새로고침** 버튼을 선택합니다.

## Garage란?

[Garage](https://github.com/eigger/garage)는 가족·홈랩용 셀프호스팅 차량 관리 앱입니다 — 정비 스케줄, 주유/충전 기록, 리마인더, OBD/GPS 주행 리포트를 제공합니다. 이 통합구성요소는 그 Garage 서버와 Home Assistant를 연결하는 역할만 하며, 실제 기록 관리·리포트·알림은 Garage 웹 UI에서 이루어집니다.

## 문제 해결과 제보 안내

- Home Assistant에서 Garage 서버 주소로 HTTP/HTTPS 접근이 가능한지, 차량 상세 페이지의 **OBD & GPS** 탭에 표시된 API 토큰과 일치하는지 확인하세요.
- **마지막 전송 시각** 센서나 **지금 전송** 버튼이 `unavailable`이면 통합구성요소 **구성**(옵션)에서 전송할 엔티티를 하나 이상 선택하세요. 위치(`entity_location`)만 단독으로 선택한 경우 상태 변화 자동 전송은 걸리지 않으므로, 트리거 센서(RPM/속도/연료/주행거리)를 함께 선택하거나 자동화에서 **지금 전송** 버튼을 호출하세요.
- 이슈나 로그를 공유할 때는 API 토큰, 개인 서버 URL, 차량 번호·차대번호(VIN), 실제 위·경도 좌표를 제거하세요. 자동화 테스트는 HTTP 응답을 대체한 실제 HA 환경에서 수행되며 실물 Garage 서버 검증을 대신하지 않습니다.

## Downloads 배지

Downloads 배지는 현재 릴리스의 첨부 asset 다운로드 합계이며 활성 설치 수나 고유 사용자 수가 아닙니다. 릴리스가 없거나 조회에 실패한 것이 다운로드 0을 뜻하지는 않습니다.
